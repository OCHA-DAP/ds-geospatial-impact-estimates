# Flood labels: one display catalog over two corpora

`platinum.py` builds the **platinum** layer the `pages/flood-labels/` viewer
reads: a versioned Portolan catalog (STAC + GeoParquet + PMTiles) over the
CEMS flood-label gold (v1, `copernicus_ems/flood/gold/`) and the UNOSAT
flood-label gold (v2, `unosat/gold/`). It is a *display* product: geometry is
simplified, attributes are the thin set the page needs, and nothing here is
an input to analysis. The fusion work reads gold, not this.

```
global/flood_labels/platinum/
  water/water.parquet + water.pmtiles              UNOSAT water at acquisition (geom_water)
  flood/flood.parquet + flood.pmtiles              UNOSAT geom_flood where separated + every CEMS extent
  valid-masks/valid_masks.parquet + .pmtiles       analysed-area masks of both
  label-index/label_index.parquet                  union of both indexes, thin columns, bbox geometry
  build_summary.json                               what was built, what had no geometry, what was skipped
  catalog.json, */collection.json, versions.json   Portolan / STAC
```

## Rules (library: `src/gie/flood_labels/platinum.py`)

- **Nothing is invented to make the corpora look alike.** A CEMS row has a
  null `sensor_class` and a null `water_area_km2` (v1 does not carry them). A
  UNOSAT row whose source never separated flood (`geom_flood` null) has no
  flood row; one that looked and found none (empty geometry) has none either.
  Both are counted in `label_sets_without_geometry`.
- **Countries** are the sources' own names: the CEMS portal's for CEMS, HDX's
  dataset record for UNOSAT (gold carries ISO3; a name with no HDX record
  raises). Three spellings are unified by an explicit alias table
  (`COUNTRY_ALIASES`); everything else is verbatim.
- **A labels row the index does not know raises.** So does a duplicate
  display key. A gold defect is not something to draw silently.
- **Implausible acquisition dates** (before 2005) are reported in the build
  summary under `index_rows_with_implausible_dates`, never dropped or
  corrected here — they are a gold finding.
- **Simplification** is Douglas-Peucker without topology preservation, applied
  part by part: CEMS 1e-4° (~10 m, analyst vectors), UNOSAT 3e-4° (~33 m: its
  polygons are polygonised rasters whose every vertex is a pixel corner, so a
  tolerance below the pixel does nothing), masks 5e-4°. Part-wise because
  GEOS's simplifier on a whole MultiPolygon was 140x slower for the same
  output (56.4 s vs 0.4 s on a 3.7M-vertex, 55,904-part row). A part the
  tolerance collapses keeps its original shape.
- **Memory is bounded per column, not per file.** A labels file is read one
  geometry column at a time (FL20200713BGD is 2 GB: ~1 GB of water WKB and
  ~1 GB of flood).

## Run

```sh
uv run --group etl --group api python pipelines/flood_labels/platinum.py \
    --unosat-work-dir <the UNOSAT gold run's work dir>   # optional: reuse its gold/ mirror
    [--codes FL20250812CPV,EMSR009] [--limit N] [--sources cems,unosat]
    [--skip-codes ...] [--push]
```

Needs `.env` with the team SAS (`DSCI_AZ_BLOB_DEV_SAS_WRITE` for `--push`),
`portolan`, `tippecanoe` and GDAL's `ogr2ogr` on PATH. Work dir defaults to
`/tmp/gie_flood_labels_platinum/` (`gold_cache/` for downloads, `catalog/` for
the Portolan catalog, `catalog/portolan.log` for tippecanoe's output).

Codes are built smallest first so progress is visible early; every code prints
one line (`[i/n] source code MB water= flood= masks= seconds`). A code named in
`--skip-codes` is recorded under `skipped_by_flag` in the summary; any other
failure stops the run. The label index published covers exactly the codes
built.

**PMTiles are generated by the builder, not by portolan.** portolan's
`add --pmtiles` streams the parquet through DuckDB spatial, which raises
`TopologyException` on the self-intersecting rings that non-topology-preserving
simplification (and CEMS's own data) contain. The builder instead writes 2-D
line-delimited GeoJSON with GDAL, **one feature per polygon part**
(`-explodecollections`: a 508k-part footprint as one feature is clipped into
every tile it touches; as parts it is tippecanoe's normal case, 3,109 s vs
1,122 s on the masks), and runs tippecanoe with a zoom ceiling (`MAX_ZOOM`:
water/flood z10, masks z9; the map overzooms past it) and
`--drop-densest-as-needed`, without portolan's
`--no-simplification-of-shared-nodes` (a global shared-vertex pass that ran
single-threaded for over ten minutes on the masks). A PMTiles newer than its
parquet is reused; `portolan add --pmtiles` then tracks it. `--tiles-only`
redoes only this stage on an existing catalog.

`--push` runs `portolan push az://global/flood_labels/platinum --force`.
`versions.json` there is a record; never hand-delete the remote directory.

## Serving

The page fetches a read-only SAS scoped to the platinum directory from the
token issuer (`?app=flood-labels&tier=platinum`; see `token-issuer/`). For
local testing without the issuer, pass `?base=<container url>/flood_labels/platinum&sas=<sas>`.
