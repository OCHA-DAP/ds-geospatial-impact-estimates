Damage Analysis Platform

What comes after the Venezuela evaluation: one place where every organisation that produces a satellite damage analysis for an event registers once, describes each product once, and sends a short delivery note each time it ships. The files stay on the event's HDX crisis page; the platform holds the description, checks the files against it, and feeds the comparison viewer. Replaces one bespoke ingest script per provider.

The provider side, working end to end on a preview environment: register an organisation, receive a sign-in link by email, describe a product and its delivery with the two HDX links, submit. Throwaway build for colleagues to try and grade the form: records go to a test folder, nothing touches production, and the address changes when the real build lands.

azurestaticapps.net ↗

What is settled. HDX hosts the files and gives each product a public link. Provider sign-up, the metadata specification, validation and notifications are ours. Three levels so nobody repeats themselves: organisation once, product once, delivery each time. Links only, never uploads.

What the real build changes. A domain of our own for the emailed links, a registry database for events, providers, sessions and each submission's state, a validator that reads every submitted file in isolation and accepts or rejects it with a named reason, and a staff review step before a new organisation can submit.
